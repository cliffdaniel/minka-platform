Flujo de trabajo

Diseñar una pieza

Parte de un componente existente y de su propósito. Define la anatomía, las variantes y los estados que necesita el flujo. Usa tokens semánticos y verifica texto largo.

Implementar en ambas superficies

Conserva los nombres de las variantes y su comportamiento. Usa controles nativos donde ayuden al teclado, al lector de pantalla o al selector del sistema.

Verificar

Prueba la pantalla real y la historia aislada. Revisa roles, contraste, foco, permisos y estados de carga, error, vacío y con datos. Usa fixtures sin información de cuentas reales.

Registrar

Actualiza el ejemplo del catálogo y el estado de adopción. Si cambia un contrato, actualiza Swagger y el registro de funcionalidades. En cambios de tokens verifica su correspondencia entre CSS y JSON.

Storybook

Web

En minka-web, ejecuta npm run storybook. Prueba la navegación con teclado y los tamaños de 390, 768 y 1440 px. Usa npm run build-storybook para generar una copia estática.

Mobile

En minka-mobile, ejecuta npm run storybook y abre la app de desarrollo con npm run android o npm run ios. Revisa interacción táctil, tamaños de texto, cambios de orientación y teclado.

Revisa primero el estado aislado y luego la página con contenido realista. Los controles de Web permiten alternar tamaños de pantalla, ejecutar las historias de interacción y revisar el panel de accesibilidad. En Mobile usa los controles y prueba gestos, VoiceOver o TalkBack y texto ampliado en el dispositivo.

Para una lista remota, implementa loadOptions con los parámetros query, cursor y signal. Devuelve options y el nextCursor cuando queden resultados. Las historias simulan esa respuesta para revisar espera, error y carga adicional.

En una lista remota, los botones del desplegable («Cargar más resultados» y «Reintentar») no deben mover el foco del campo; si lo hicieran, el selector se cerraría y cancelaría la carga.

Pruebas de historias

Cada historia tiene una prueba automática. En Web, npm run test:stories compila el catálogo y, en un navegador, comprueba que cada historia renderiza, que su interacción termina sin fallos, que no hay errores de consola y que no hay problemas graves de accesibilidad. En Mobile, npm test renderiza todas las historias y falla ante cualquier error; no ejecuta las interacciones ni sustituye la revisión en dispositivo. Al crear una historia nueva, ejecuta la prueba de su plataforma antes de entregar.
